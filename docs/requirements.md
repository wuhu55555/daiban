# 需求设计文档：代办事项

> 素材来源：需求对齐对话（2026-09-03，9 条疑问逐条拍板，全部按默认假设确认）。
> 状态：已确认

## 1. 项目背景与目标
- **背景**：日常待办依赖零散记录（纸质便签 / 备忘录 / 聊天置顶），无集中管理入口，无法区分轻重缓急，完成状态靠脑记，容易遗漏。需要一个轻量、打开即用、无后端依赖、本地持久化的代办事项工具。
- **目标**：一个纯前端（Vue 3 + TypeScript）代办事项应用，用户可快速记录、管理、筛选待办，刷新页面数据不丢失。
- **成功指标**：打开页面即可走通「新增 → 查看 → 勾选完成 → 筛选」完整闭环；数据存 localStorage，刷新后完整保留；零部署成本（静态托管即可）。

## 2. 用户与角色
| 角色 | 描述 | 核心诉求 |
|------|------|----------|
| 个人用户 | 需要管理日常待办的个人（单机单浏览器使用） | 快速新增、一眼看清总数/未完成数与优先级、随时勾选完成、刷新不丢 |

## 3. 核心业务场景
- **入口**：打开页面 → 看到顶部统计（总数 / 未完成数）+ 事项列表 + 新增表单，可直接开始记录
- **主流程**：新增（标题必填 ≤50 字、内容、优先级）→ 列表按「未完成在前、已完成在后，组内按创建时间倒序」展示 → 勾选完成/取消 → 编辑（标题/内容/优先级）→ 删除（原生 confirm 确认）→ 切换筛选（全部/未完成/已完成）
- **完成后的反馈**：列表即时刷新、统计数字同步更新、已完成项加删除线并沉底

## 4. 功能清单
### 第一版必须做（MVP）
- [x] 事项列表展示：显示总数与未完成数
- [x] 添加事项：标题（必填）、内容、优先级（高/中/低）
- [x] 编辑事项：标题、内容、优先级（完成状态不走编辑，由勾选切换）
- [x] 删除事项：删除前原生 confirm() 确认
- [x] 勾选完成 / 取消完成
- [x] 筛选：全部 / 未完成 / 已完成
- [x] localStorage 持久化，刷新不丢

### 明确不做
- [x] 后端 / 账号体系 / 多端同步（纯前端单机，数据仅存本浏览器）
- [x] 批量操作、拖拽排序（超出需求范围）
- [x] 按优先级排序（优先级仅作展示标记，不参与排序）
- [x] 跨标签页实时同步（不监听 storage 事件）

## 5. 非功能需求
- **性能**：单用户本地数据，量级 ≤ 数百条，无并发；列表全量渲染即时可见；localStorage 同步读写
- **安全**：纯本地数据，无网络传输；渲染经 Vue 自动转义，无 XSS 注入面；不涉及登录与敏感信息
- **其他**：目标现代浏览器（Chrome / Safari / Edge）；Node.js 仅开发期需要，产物为纯静态资源

## 6. 数据来源
- 系统内录入（用户手动新增）；持久化于浏览器 localStorage（key：`todos`）

## 7. 验收标准
- 走通一次完整流程：新增 → 列表出现 → 编辑 → 勾选完成（删除线 + 沉底）→ 筛选查看 → 删除（confirm）→ 刷新后数据完整保留
- 边界校验：空标题提交被拦截；标题超过 50 字无法输入；localStorage 数据损坏时重置为空列表且不报错

## 8. 优先级与版本规划
| 优先级 | 功能 | 归属版本 | 备注 |
|--------|------|----------|------|
| P0 | 列表展示 + 总数/未完成数统计 | MVP | 核心入口 |
| P0 | 新增 / 编辑 / 删除 / 勾选完成 | MVP | 完整 CRUD |
| P0 | 筛选（全部/未完成/已完成） | MVP | 需求明确 |
| P0 | localStorage 持久化 | MVP | 「刷新不丢」为硬需求 |
| P1 | 核心逻辑单测（排序/筛选/校验/存储） | MVP | 满足 CHECKLIST 测试层门禁 |
| P2 | 空态提示、交互细节打磨 | MVP 收尾 | 不影响核心流程 |
