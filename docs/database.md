# 数据库设计文档：代办事项

> 本项目**无传统数据库**，持久化层为浏览器 localStorage（Web Storage API）。本文档定义 localStorage 的数据结构、读取契约与校验兜底策略。
> 状态：已确认

## 1. 数据库选型
- 数据源：浏览器 localStorage，单一 key 存储
- 存储 key：`todos`（固定常量，集中管理，不散落硬编码）
- 容量上限：约 5MB；按单条 ≤ 200B 估算可容 2 万+ 条，远超本场景量级
- 选型理由：需求指定「数据存 localStorage，刷新不丢」；纯前端单机、零后端成本、零部署

## 2. 表关系概览（ER 文字版）
- 单一集合 `todos`，无关联表、无外键、无引用关系
- 结构：`todos: Todo[]`（对象数组的 JSON 序列化，整体存于一个 key）

```
todos ── 1 ── N Todo  （无任何关联实体）
```

## 3. 表清单
| 存储 key | 用途 | 归属模块 |
|----------|------|----------|
| todos | 事项集合（Todo[] 的 JSON 字符串） | 代办事项 |

## 4. 字段设计
### key：todos（元素为 Todo）
| 字段名 | 类型 | 约束 | 说明 |
|--------|------|------|------|
| id | string | 必填，唯一 | `crypto.randomUUID()` 生成 |
| title | string | 必填，去空格后 1~50 字 | 标题 |
| content | string | 可空 | 内容描述 |
| priority | `'high' \| 'medium' \| 'low'` | 必填，默认 `'medium'` | 优先级 |
| completed | boolean | 必填，默认 `false` | 完成状态 |
| createdAt | number | 必填 | 创建时间戳（毫秒） |

**读取校验契约**（对应需求 Q5 确认项）：`JSON.parse` 失败 → 重置为空数组并 console 告警；解析成功但非数组，或数组元素缺字段/类型不符 → 丢弃非法项（合法项保留）；整体异常 → 重置为空数组。保证应用永不因脏数据崩溃。

## 5. 索引设计
- localStorage 为单 key 顺序存储，**无索引概念**。查询依赖内存数组过滤/排序，数据量级小（数百条内 O(n) 可接受），无需额外索引结构。

## 6. 数据量与策略
- 预估数据量：个人场景 ≤ 数百条，远低于 localStorage 容量上限
- 分页策略：不适用（前端全量渲染；当前 MVP 不做分页，若未来数据量剧增再评估）
- 归档 / 清理策略：由用户手动删除；无自动清理任务

## 7. 迁移与初始化
- 迁移方式：**无版本化迁移**。写入时始终覆盖 key `todos` 最新结构；读取时按 §4 校验契约兜底，旧结构/脏数据自动降级处理
- 初始化数据：首次使用为空数组；**不预置示例数据**（避免干扰真实使用）
